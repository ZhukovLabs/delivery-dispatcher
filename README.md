# Диспетчер доставки

Веб-инструмент для администратора точки доставки еды. Раскидывает готовые
заказы по курьерам и строит маршруты так, чтобы последний заказ приехал
как можно раньше (MinMax-VRP, OR-Tools). Времена считаются по реальным
дорогам: OpenRouteService, запасной вариант OSRM, на крайний случай оценка
по прямой.

## Установка и запуск

```
pip install -r requirements.txt
python app.py          # или двойной клик по run.bat
```

Откроется на http://127.0.0.1:5050

## Настройка (config.ini)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ors_key` | нет | Ключ openrouteservice.org (матрицы по реальным дорогам). Без ключа работает на публичных OSRM |
| `host` | `127.0.0.1` | `0.0.0.0` открывает доступ из сети: обязательно смените пароль администратора |
| `port` | `5050` | Порт панели |
| `admin_email` | `admin@local` | Логин администратора, создаётся при первом запуске |
| `admin_password` | `admin` | Начальный пароль администратора. Смените после первого входа! |
| `db_path` | `dispatcher.db` | SQLite-база: данные и пользователи переживают перезапуск |
| `tg_bot_token` | нет | Токен бота Telegram для кнопки 📤 (пока пусто, поле chat id просто хранится) |

## Пользователи и доступ

- Вход по **email + паролю** (пароли хранятся как PBKDF2-хэши).
- Первый запуск создаёт администратора из `config.ini` (`admin@local / admin`).
  Сразу смените пароль: лист «Ещё», раздел «Доступ».
- Администратор там же добавляет и удаляет пользователей, выдаёт права админа.
- Каждый может сменить свой пароль. От дурака защищено: удаление себя,
  дубликаты email, пароли короче 4 символов, подбор (пауза после серии
  неверных вводов).

## Как пользоваться

1. **Депо**: точка выдачи. Поиск по адресу с подсказками или клик по карте.
2. **Курьеры** по именам. «На базе» значит отдать сейчас, «В пути» значит
   следующим (поле «через N мин вернётся» сдвигает его ETA), «Недоступен»
   из расчёта выключен.
3. **Готовые заказы**: адресом или кликом по карте. Поиск понимает номера
   домов, даже если дом не размечен в OSM (интерполяция по чётной и
   нечётной стороне). ✓ отмечает выданный заказ, ✕ отменённый; оба идут
   в историю дня (счётчик в шапке).
4. **⚡ Рассчитать развозку**: каждый курьер получает свой набор заказов,
   порядок объезда и ETA по часам (⏱ 14:35 +8 мин). Карточка «отдать
   сейчас» и есть задание для курьера на базе; 📋 копирует маршрут текстом.
5. **⚖️ Ждать ли возвращающегося курьера**. Если кто-то «в пути», расчёт
   сам сравнит «отправить всё сейчас» и «разделить с ним» по времени
   последней и средней доставки, применит выгодный вариант и подскажет,
   какие заказы придержать. Порог выгоды: 5 минут по последней доставке
   или 2 по средней. Вариант можно переключить и вручную.
6. **Дедлайны**. У заказа есть поле «к обещанному времени» (⏱). План
   старается успеть (штраф за опоздание выше, чем у приоритета) и прямо
   пишет «опоздание ~N мин», если не выходит.
7. **Авто-приоритет по возрасту** (выключен по умолчанию, включается
   параметром). Заказ ждёт дольше N минут (например, 20) — бейдж ⏱ N мин,
   и в расчёте он едет как приоритетный, сам.
8. **Мультивыезды**. Если заказов больше, чем влезает в сумки, курьер
   после первого заезда возвращается на базу и едет снова («Заезд 2»,
   старт сдвигается на время возврата и перезагрузки).
9. **Ручные правки плана**. Остановку можно перетащить мышью на карточку
   другого курьера: ETA пересчитаются мгновенно, план помечается «✋ правка».
10. **Всё пересчитывается само**. Добавили заказ, курьер приехал или
    уехал — план обновится через пару секунд, кнопка нужна только чтобы
    потребовать совет «ждать/не ждать».
11. **Часы пик** (включается в параметрах): утро и вечер в Гомеле едут
    медленнее (×1.2–1.35), ночь быстрее (×0.9).
12. **Неделя и отчёт дня**: «Ещё» → графики за 7 дней, доля вовремя по
    дедлайнам; «🖨 Отчёт дня» открывает печатную страницу (Ctrl+P → PDF).
13. **Telegram (заготовка)**: у курьера поле chat id; заполните
    `tg_bot_token` в config.ini — и на карточке маршрута появится кнопка
    📤 отправки. Без токена поле просто хранится.
14. **🌙 Тёмная тема** в шапке, запоминается.
15. **Жизненный цикл заказа**. ✓ или «Выдать» на карточке маршрута — заказ
    уезжает в «🛵 В развозке» и уходит из расчёта; ↩ возвращает в очередь,
    «🏁 вернулся» у курьера сдаёт все его заказы в историю как доставленные.
    Удаление курьера возвращает его заказы в очередь. Ctrl+Z отменяет
    последнее действие (выдача, возврат, отмена, удаление).
16. **Таймлайн дня**: под планом полосы заездов каждого курьера по часам.
17. **Подсветка «горит»**: заказ с просроченным дедлайном помечается 🔥.
18. **Подъезд по районам**: минуты на парковку/подъезд — центр и окраины
    задаются отдельно, добавляются к каждой доставке.

## История и отчёты

Лист «Ещё», раздел «История»: день, 2 дня, неделя, месяц. Выдано и отменено,
средний цикл заказа (от создания до вручения), список с курьером и временем.
**⬇ CSV** выгружает то же самое для Excel. **💾 Бэкап БД** (у админа)
скачивает снимок базы одним кликом. Там же «Неделя» и ссылка на отчёт дня.

## Параметры расчёта

- скорость курьера (км/ч, 60): запасной режим, когда роутинг недоступен;
- время вручения заказа (мин, 5): добавляется к каждой доставке;
- макс. заказов у курьера за один заезд (5);
- коэффициент пробок (×1.25 к времени дороги);
- светофоры (15 с/км пути);
- авто-приоритет после N минут ожидания (0 = выключено);
- перезагрузка между заездами (10 мин);
- подъезд: центр (4 мин) и окраины (2 мин) добавляются к каждой доставке
  (граница — 2.5 км от депо);
- галочка «часы пик»: почасовые коэффициенты Гомеля.

## Устройство и надёжность

- **Маршрутизация**: ORS (лимит 2000 запросов в сутки, мягкий предел 1800,
  авто-пауза при 429) → OSRM FOSSGIS → OSRM demo → прямая линия. Провайдер
  виден под часами плана.
- **Данные**: SQLite. Курьеры, заказы, депо, настройки, план и история
  переживают перезапуск: после старта план пересчитается сам, если его нет.
- **Доступ**: email и пароль, роли, сессии на 12 часов, пауза после 5
  неверных паролей. Ошибки API отдаются в JSON.
- **Логи**: `dispatcher.log` (ротация 1 МБ × 3), `/health` для мониторинга.

## Ограничения

- Геокодинг на публичных Nominatim/Photon: нужен интернет, 1 запрос в секунду.
- Позиции курьеров «в пути» не отслеживаются по GPS: считается, что каждый
  стартует с депо.
- Пробки усреднённые, не живой трафик.
