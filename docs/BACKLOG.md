## Дельта-пейлоады для WS-пушей состояния

**Идея.** Сейчас каждое изменение депо рассылается полным payload'ом
`/api/state` (~8.5 КБ JSON). Слать только diff (изменённые поля) с
версионированием: клиент применяет дельту к локальной копии.

- Оценка выигрыша: ~10× меньше трафика на пуш (позиция курьера — это
  ~200 байт изменений против 8.5 КБ полного состояния).
- Когда браться: медленные каналы у диспетчеров (моб. интернет), >10
  одновременных курьеров с live-гео, оплата за трафик.

**Более простая альтернатива (сделать сначала, если понадобится):**
включить сжатие WS-фреймов (permessage-deflate в python-socketio /
`websocket_extra_options`) или gzip на уровне payload — JSON состояния
жмётся в ~5–10× без изменений протокола и клиента.

**Подводные камни дельт:**

- порядок применения и потеря промежуточных пушей при reconnect
  (лечится: после reconnect клиент всё равно делает refetch полного
  состояния — уже реализовано в `useDispatchState`);
- версионирование дельт и «слишком старая версия» → полный refetch;
- усложнение `_payload`/`_broadcast`: нужен снимок для diff'а.
